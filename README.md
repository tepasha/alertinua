## 📌 Опис проєкту

**`alertinua`** — прошивка для мікроконтролера **ESP32** (плата LILYGO
T-Display, дисплей ST7789 240×135, SPI), написана на **ESP-IDF** (FreeRTOS).
Пристрій автономно підключається до Wi-Fi, опитує REST API
[alerts.in.ua](https://alerts.in.ua/) про статус повітряної тривоги у
вибраній області України, показує карту з підсвіченими областями на
дисплеї, вмикає сирену (п'єзозумер) і світлодіодну індикацію, а яскравість
підсвітки автоматично підлаштовує під освітлення в кімнаті.

## ✨ Особливості

- 🧠 **RTOS-архітектура:** 7+ задач FreeRTOS зі своєю чіткою зоною
  відповідальності, явна стейт-машина (`app_state`), синхронізація через
  mutex і queue — без блокуючих `delay()` в основній логіці. Детальніше —
  [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
- ⚡ **Мережа:** `esp_http_client` + TLS (mbedTLS) з валідацією JSON-відповіді
  (cJSON), автоматичне перепідключення Wi-Fi з експоненційним backoff.
- 🌐 **Wi-Fi Provisioning:** SoftAP + вебсторінка налаштування (ручний вхід —
  довге натискання кнопки BOOT, або автоматично після серії невдалих спроб).
- 💡 **Адаптивна яскравість:** ADC-датчик освітлення (LDR) + PI-регулятор
  (feedback control) керує підсвіткою дисплея через PWM.
- 🔔 **Індикація:** мапа областей на дисплеї, п'єзозумер (неблокуюча сирена
  у власній задачі), Status LED і Wi-Fi LED.
- 🛡️ **Надійність:** Task Watchdog на кожній задачі, валідація вхідних
  даних (JSON/HTTP), пристрій не зависає при обірваному Wi-Fi чи битій
  відповіді API.
- 📊 **Спостережуваність:** у логах — час HTTP+JSON окремо (мкс) і
  періодичний звіт по завантаженню CPU кожної задачі.

## 🧩 Архітектура

Короткий підсумок (повна версія з діаграмами — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)):

```
Wi-Fi (wifi_task) ──┐
                     ├─► fetch_task ──(HTTP+JSON)──► alert_queue ──► render_task ──► дисплей
Кнопка (ISR+queue) ──┘                                                  │
                                                                         ├─► buzzer_task (сирена)
Датчик світла (ADC) ──► brightness_ctrl_task ──► підсвітка (PWM)        └─► indicators (LED)

Усі задачі читають/пишуть спільний стан через app_state (mutex).
```

Модулі-компоненти (кожен зі своїм `CMakeLists.txt`, без циклічних
залежностей): `app_state`, `button`, `buzzer`, `backlight`, `light_sensor`,
`brightness_ctrl`, `indicators`, `wifi_manager`, `scraping` (HTTP + JSON
парсинг), `map` (рендеринг мапи областей). Усі задачі FreeRTOS лежать
окремо, у папці `task/` у корені проєкту (по підпапці-компоненту на задачу).

## 🛠️ Вимоги

- **Фреймворк:** ESP-IDF v5.0+
- **Плата:** LILYGO T-Display (оригінальний ESP32, ST7789 240×135 SPI)
- **Токен:** API-ключ [alerts.in.ua](https://alerts.in.ua/)
- Додатково (див. [docs/PCB.md](docs/PCB.md)): фоторезистор (LDR) + резистор
  10кОм для датчика освітлення, 2 світлодіоди з резисторами для індикації
  (опційно — без них прошивка теж працює, просто ці GPIO лишаться невживані)

## 🔌 Апаратне підключення (Hardware)

Реальні піни, які використовує прошивка (не приклад — саме ці константи
в коді):

| Периферія | Опис | GPIO | Компонент |
| --- | --- | --- | --- |
| Дисплей (SPI) | ST7789 240×135, MOSI/SCLK/CS/DC/RST | 19 / 18 / 5 / 16 / 23 | `map` |
| Підсвітка дисплея (PWM) | LEDC, регулюється автоматично | 4 | `backlight` |
| П'єзозумер (PWM) | LEDC, сирена при тривозі | 25 | `buzzer` |
| Кнопка налаштування | BOOT, вбудована на платі, переривання | 0 | `button` |
| Status LED | Блимає під час активної тривоги | 2 | `indicators` |
| Wi-Fi LED | Горить/блимає залежно від статусу Wi-Fi | 15 | `indicators` |
| Датчик освітлення (ADC1_CH6) | LDR + резистор 10к, для авто-яскравості | 34 | `light_sensor` |

Принципова схема з'єднань — [docs/PCB.md](docs/PCB.md) (плата не
розводилась/не виготовлялась, лише схема й аргументація рішень).
