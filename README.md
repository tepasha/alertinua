## 📌 Опис проєкту

**`alertinua`** — прошивка для плати **LILYGO T-Display** (ESP32, дисплей
ST7789 240×135), написана на **ESP-IDF** з FreeRTOS. Пристрій сам
підключається до Wi-Fi, раз на хвилину опитує API
[alerts.in.ua](https://alerts.in.ua/) і показує на дисплеї карту України:

| На екрані | Що означає |
| --- | --- |
| 🟥 червона область | повітряна тривога по всій області |
| 🟧 янтарна область | тривога лише в частині області (район, громада) |
| напис **ERR** | дані отримати не вдалося — старі тривоги не показуються |

Коли тривога оголошена на всю **вибрану** область, вмикається сирена
(п'єзозумер) і блимає світлодіод. Яскравість підсвітки автоматично
підлаштовується під освітлення в кімнаті. Від вбудованого акумулятора
пристрій працює без USB, а рівень заряду видно на сторінці налаштувань.

## ✨ Особливості

- 🧠 **FreeRTOS:** 7 задач, кожна зі своєю відповідальністю, обмін через
  черги, спільний стан під м'ютексом — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
- 📡 **Легкий обмін з API:** IoT-ендпоінт alerts.in.ua повертає рядок із
  27 символів (`A`/`P`/`N` на кожну область) — ~30 байт замість кілобайтів
  JSON, лише повітряні тривоги.
- 🌐 **Веб-налаштування:** вибір області й Wi-Fi-мережі на сторінці
  пристрою, без перепрошивки. Зберігається в NVS.
- 💡 **Адаптивна яскравість:** фоторезистор + ПІ-регулятор з anti-windup
  керує підсвіткою через ШІМ.
- 🔋 **Автономність:** акумулятор Li-Pol 3.7 В 300 мА·год у штатному
  роз'ємі плати; заряд (%, В) — на веб-сторінці й у лозі.
- 🛡️ **Надійність:** Task Watchdog на кожній задачі, валідація відповіді
  API, перепідключення Wi-Fi з експоненційною затримкою (2 → 60 с).
- 🔐 **Секрети поза git:** API-токен у файлі `.env`, TLS з перевіркою
  сертифіката.

## 🔌 Підключення

![Схема підключення](docs/wiring.svg)

| Периферія | Деталі | GPIO | Компонент коду |
| --- | --- | --- | --- |
| Дисплей ST7789 (SPI) | вбудований: MOSI / SCLK / CS / DC / RST | 19 / 18 / 5 / 16 / 23 | `map` |
| Підсвітка дисплея | вбудована, ШІМ (LEDC) | 4 | `backlight` |
| Кнопка налаштування | вбудована кнопка BOOT, переривання | 0 | `button` |
| П'єзозумер | пасивний, через резистор 220 Ом, ШІМ (LEDC) | 25 | `buzzer` |
| Світлодіод тривоги | через резистор 330 Ом | 2 | `indicators` |
| Світлодіод Wi-Fi | через резистор 330 Ом | 15 | `indicators` |
| Датчик освітлення | фоторезистор + резистор 10 кОм, ADC1_CH5 | 33 | `light_sensor` |
| Акумулятор Li-Pol | у штатний роз'єм BAT; напругу плата подає через дільник 1:2, дільник вмикає GPIO14 | 34 (АЦП), 14 (внутрішні) | `battery` |
| Вимикач живлення | з фіксацією, розриває червоний провід «+» акумулятора | — | — |

**Що потрібно докупити:** фоторезистор, резистори 10 кОм, 220 Ом і
2 × 330 Ом, два світлодіоди, пасивний п'єзозумер, акумулятор Li-Pol
602030 3.7 В 300 мА·год із платою захисту, вимикач із фіксацією
(перемикач або клавішний) для живлення від акумулятора. Без світлодіодів
прошивка працює як звичайно. Без датчика вхід GPIO33 «висить у повітрі»,
і яскравість підсвітки стрибатиме випадково — тож для автояскравості
датчик потрібен.

> Перед підключенням акумулятора звірте роз'єм і **полярність** з
> маркуванням `+`/`−` на платі: у дешевих акумуляторів дроти в роз'ємі
> бувають переставлені, а переплутана полярність може пошкодити плату.
> Вимикач ставиться в розрив червоного проводу «+». Від USB плата
> працює й при вимкненому вимикачі, але батарея тоді не заряджається.

> Датчик освітлення підключайте лише до пінів ADC1 (32, 33, 36–39): ADC2
> під час роботи Wi-Fi недоступний. GPIO34 на гребінку не виведений — він
> зайнятий вимірюванням напруги батареї.

Опис схеми й вибору деталей — [docs/PCB.md](docs/PCB.md).

## 🛠️ Збірка й прошивка

Потрібні [VS Code](https://code.visualstudio.com/) з розширенням
**PlatformIO**. Платформа `espressif32` встановлює ESP-IDF (перевірено на
6.0.1) і тулчейн сама.

1. **Токен API.** Отримайте токен на [alerts.in.ua](https://alerts.in.ua/),
   скопіюйте `.env.example` у `.env` і впишіть його:
   ```
   ALERTINUA_API_TOKEN=ваш-токен
   ```
   `.env` і згенерований з нього `env/env_config.h` у `.gitignore` —
   токен не потрапляє в git.
2. **Wi-Fi за замовчуванням (необов'язково).** Мережу простіше задати
   через [веб-налаштування](#-налаштування-пристрою). Або заздалегідь у
   `pio run -t menuconfig` → *Alertinua Configuration → Wi-Fi*.
3. **Збірка й прошивка:**
   ```
   pio run -t upload
   pio device monitor
   ```

Інші параметри (область за замовчуванням, інтервал опитування, межі
яскравості, максимальна тривалість сирени) — у
`pio run -t menuconfig` → *Alertinua Configuration*.

## ⚙️ Налаштування пристрою

1. Утримайте кнопку **BOOT** 3 секунди. Пристрій також сам переходить у
   цей режим після 10 невдалих спроб підключитися до Wi-Fi.
2. Підключіться до Wi-Fi-мережі **ESP32-Setup**.
3. Відкрийте **http://192.168.4.1/**.
4. Угорі сторінки — заряд батареї (%, В) або «Живлення від USB». Виберіть область. Щоб змінити Wi-Fi, впишіть SSID і пароль; якщо лишити
   SSID порожнім, збережена мережа не зміниться.
5. Натисніть **«Зберегти і перезавантажити»**.

## 🧩 Архітектура

```
API alerts.in.ua ──► fetch_task ──► alert_queue ──► render_task ──► дисплей
        ▲                                               │
    wifi_task                                           └──► buzzer_task (сирена)

фоторезистор ──► brightness_task (ПІ-регулятор) ──► підсвітка (ШІМ)
кнопка BOOT ──► button_task ──► режим налаштування
monitor_task: раз на 30 с — навантаження CPU кожної задачі і заряд батареї
```

Структура проєкту:

```
task/          задачі FreeRTOS — по підпапці-компоненту на кожну
components/    драйвери й логіка без власних задач:
               adc_shared, app_state, backlight, battery, brightness_ctrl,
               button, buzzer, indicators, light_sensor, map, scraping,
               settings, wifi_manager
src/           app_main() і Kconfig.projbuild (параметри menuconfig)
env/           env.py: .env → env/env_config.h перед кожною збіркою
test_host/     юніт-тести, що запускаються на комп'ютері
test_apps/     юніт-тести для запуску на самій платі
docs/          архітектура, схема підключення, опис апаратної частини
```

Детально — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## 🧪 Тести

Парсер відповіді API, ПІ-регулятор яскравості і крива заряду батареї —
«чисті» функції без
залежності від обладнання, тому тестуються на звичайному комп'ютері
(фреймворк Unity):

```
sudo apt-get install --no-install-recommends libcjson-dev
make -C test_host run
```

Набір для запуску на платі — у `test_apps/` (див. коментар у
`test_apps/test_main.c`).
